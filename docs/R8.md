# Compilación release con R8

R8 se ejecuta en la **aplicación Android integradora**. El AAR incluye sus reglas de consumo y las aplica Gradle automáticamente. No es necesario copiar reglas que conserven toda la SDK.

## Configuración de la app

```groovy
android {
    buildTypes {
        release {
            minifyEnabled true
            shrinkResources true
            proguardFiles getDefaultProguardFile('proguard-android-optimize.txt'),
                'proguard-rules.pro'
        }
    }
}
```

Con AGP 9.0.1, retira `android.nonFinalResIds=false`, `android.r8.strictFullModeForKeepRules=false` y `android.r8.optimizedResourceShrinking=false` de `gradle.properties` si existen. Usa los valores predeterminados de R8 y conserva los demás ajustes de integración documentados en el README.

El archivo `app/proguard-rules.pro` debe contener solamente las reglas adicionales de reflexión propias de tu aplicación. No agregues `-keep class com.becomedigital.** { *; }`, `-keep class aws.smithy.kotlin.runtime.** { *; }`, `-dontobfuscate` ni `-ignorewarnings` como solución general: limitan la optimización o esconden errores reales.

## Qué conserva el AAR

- Campos JSON de respuestas tipadas y modelos leídos mediante reflexión, incluidos los nombres de los estados públicos.
- Recursos de texto `intro_*` y `atdp_*` que la app puede personalizar y que se buscan por nombre.
- Las reglas de los proveedores continúan aplicándose desde sus dependencias. Mantén todas las dependencias y versiones indicadas en el README.

La API pública conserva sus nombres en el AAR distribuido. R8 reduce y optimiza el código al compilar la app final; no se ofrece un AAR previamente ofuscado. El ahorro varía según las funciones y dependencias usadas. R8 no reduce el tamaño de las bibliotecas nativas ni garantiza una reducción determinada del APK.

## Validación y diagnóstico

Compila `./gradlew :app:assembleRelease` o `./gradlew :app:bundleRelease`. Conserva `app/build/outputs/mapping/release/mapping.txt` de cada versión para interpretar trazas ofuscadas; no lo publiques junto con credenciales ni datos personales.

Antes de distribuir la app, prueba **el release optimizado** en dispositivo físico: permisos, captura automática y manual, ambas caras del documento, reintento, validación facial, cancelación, textos personalizados y manejo de respuestas y errores. Una compilación exitosa no reemplaza estas pruebas.

Referencia: [optimización para autores de librerías Android](https://developer.android.com/topic/performance/app-optimization/library-optimization).
